## 2026-10-02 · D01 · Работаем в ветке `site-v2`, `main` не трогаем

- **Решение.** Вся работа — локальные коммиты в ветку `site-v2`, созданную от `main` (`02b1b69`). Ничего не пушится.
- **Почему.** Живой сайт сейчас отдаётся GitHub Pages из корня `main` (`index.html` + `CNAME`). Новый сайт — собираемый (исходники ≠ готовый HTML), и push в `main` до переключения хостинга на Cloudflare Pages сломал бы www.terroir-app.com.
- **Альтернативы.** Коммитить в `main` и предупредить в README (рискованно: один `git push` — и сайт лежит); собирать в `docs/` для GitHub Pages (держит нас на GH Pages и мешает `_headers`/`_redirects`).

## 2026-10-02 · D02 · Стек — Astro 7 (статическая сборка), без Tailwind

- **Решение.** Astro `7.3.5` + `@astrojs/sitemap`, собственные компоненты, собственный CSS на custom properties. Node 22 через nvm, `.nvmrc` = `22`. Зависимости только локальные (`node_modules`), версии зафиксированы (`--save-exact`).
- **Почему.** По правилу брифа: `node -v` после `nvm use 22` = v22.23.3 ≥ 20 → Astro. Системный node — v18, поэтому в скриптах и README явно `nvm use`. Tailwind не берём: дизайн-система «Погребной журнал» — это несколько десятков токенов и редакционная типографика; ручной CSS получается короче, читаемее и легче (одна таблица стилей ~20 КБ), без ещё одного слоя сборки.
- **Альтернативы.** Hugo 0.167 extended (тоже установлен; был бы выбран при Node < 20); Astro + Tailwind (допустимо, но избыточно для такого объёма).

## 2026-10-02 · D03 · Старый лендинг — в `legacy/index.html`, CNAME — в корне и в `public/`

- **Решение.** `git mv index.html legacy/index.html` (история сохранена). `CNAME` остаётся в корне репозитория и скопирован в `public/CNAME`, чтобы попасть в `dist/`.
- **Почему.** Требование брифа; `public/` в Astro — аналог `static/` в Hugo (копируется в сборку как есть). `legacy/` в сборку не попадает.
- **Альтернативы.** Удалить старый лендинг (запрещено), положить в `public/legacy/` (тогда он опубликуется с устаревшим позиционированием — не нужно).

## 2026-10-02 · D04 · Шрифты — Cormorant (заголовки) + Inter (текст), self-hosted из @fontsource-variable

- **Решение.** Заголовки — Cormorant (variable, wght 300–700, normal+italic), текст — Inter (variable). Подмножества: latin, latin-ext, cyrillic. woff2 подключаются через `@font-face` в нашем CSS, файлы копируются в `public/fonts/`, лицензия SIL OFL 1.1 лежит рядом (`public/fonts/OFL-*.txt`).
- **Почему.** Cormorant — выразительная гаральдовая антиква с полноценной кириллицей и красивым курсивом — то, что нужно «редакционному журналу». Inter уже стоял в старом лендинге (как системное имя) — нейтральный гротеск с табличными цифрами (`tnum`). Обе — OFL. Никаких запросов к Google Fonts/CDN.
- **Альтернативы.** Cormorant Garamond (уже, менее контрастный курсив), Literata (книжная, но менее выразительная в крупном кегле), системный стек (дешевле, но теряем характер).

## 2026-10-02 · D05 · i18n — встроенная i18n Astro, EN в корне, RU в `/ru/`

- **Решение.** `i18n: { defaultLocale: 'en', locales: ['en','ru'], routing: { prefixDefaultLocale: false } }`. Строки интерфейса — `src/i18n/en.ts`, `src/i18n/ru.ts`. Страницы — отдельные файлы `src/pages/*.astro` и `src/pages/ru/*.astro`, тело страниц — компоненты `src/content-pages/<page>.astro`, принимающие `lang`.
- **Почему.** Тексты на двух языках сильно отличаются по ритму и вёрстке (не дословный перевод), поэтому контент живёт рядом с разметкой, а общие строки — в словарях.
- **Альтернативы.** Content collections с Markdown `*.en.md`/`*.ru.md` (как в Hugo) — удобно для статей, но для лендинговых страниц с мокапами и сетками пришлось бы тащить MDX; оставлено для будущего «Журнала».

## 2026-10-02 · D06 · Логотип, favicon и OG генерируются скриптом из наших же шрифтов

- **Решение.** `scripts/build-brand.mjs` (Node, без новых зависимостей): буквы Cormorant/Inter → SVG-контуры через `fontkitten` (уже в node_modules как зависимость Astro), растр — через `sharp` (тоже уже есть). Генерирует `src/assets/brand/logo.svg`, `mark.svg`, `public/favicon.svg|ico`, `apple-touch-icon.png`, `icon-192/512.png`, `public/og/og-{en,ru}.png` (1200×630). Результат закоммичен — скрипт в CI не нужен.
- **Почему.** Логотип в контурах не зависит от шрифтов у зрителя; OG-PNG без внешних тулов (требование брифа); ICO собирается вручную из PNG (формат это допускает).
- **Ограничение.** `fontkitten` не умеет применять ось `wght` у variable-шрифта к контурам, поэтому глифы берутся в начертании по умолчанию (Light 300) и «утяжеляются» обводкой `stroke` того же цвета. Для временного логотипа это приемлемо; настоящий логотип рисуется дизайнером.
- **Альтернативы.** Рисовать буквы руками (долго и хуже), использовать `<text>` в SVG (зависит от шрифтов у зрителя, sharp/rsvg не видит наши woff2).

## 2026-10-02 · D07 · Канонический домен — apex `terroir-app.com`, www → 301 на apex

- **Решение.** `site = https://terroir-app.com`; редирект `www.terroir-app.com/*` → `https://terroir-app.com/:splat` (301) делается в Cloudflare (Bulk Redirect / Redirect Rule), т.к. `_redirects` Pages не умеет матчить по хосту. Подробно — docs/DEPLOY.md.
- **Почему.** Короче в шаринге и в OG, старый лендинг уже указывал canonical на `https://terroir-app.com/`. CNAME-файл (`www.terroir-app.com`) нужен только GitHub Pages и не мешает Cloudflare.
- **Альтернативы.** www как канонический — соответствует текущему CNAME GitHub Pages; при выборе этого варианта поменять `SITE.url` в `src/config.ts` и правило редиректа. Вопрос оставлен Антону.

## 2026-10-02 · D08 · JS — один ES-модуль через бандлер Astro, без инлайн-скриптов

- **Решение.** `src/scripts/site.js` (18+, мобильное меню, форма) подключается `<script>` в `Base.astro` → Vite кладёт его внешним файлом с хэшем (~2 КБ). Мобильное меню — `<details>`, FAQ — `<details>`, всё работает без JS. CSS тоже всегда внешним файлом (`inlineStylesheets: 'never'`).
- **Почему.** Позволяет CSP `script-src 'self'` и `style-src 'self'` без `'unsafe-inline'`. JSON-LD (`type=application/ld+json`) CSP не блокирует — это данные, не скрипт.
- **Следствие.** В разметке нет атрибутов `style=""`: полоса окна питья рисуется SVG с процентными `x/width/cx`, задержки анимации — через `:nth-child`. `scripts/check.mjs` падает, если появится инлайн-скрипт/стиль.

## 2026-10-02 · D09 · Форма раннего доступа: mailto сейчас, endpoint — одной строкой позже

- **Решение.** `EarlyAccessForm.astro` + `SITE.form.endpoint`. Пусто → JS валидирует поля (доступные ошибки с `aria-invalid`/`aria-describedby`) и открывает `mailto:` с собранными темой и телом; без JS форма отправляется как `action="mailto:…" enctype="text/plain"` (нативная HTML-валидация `required`), плюс под формой обычная ссылка mailto с шаблоном письма. Задан → обычный POST `application/x-www-form-urlencoded`.
- **Почему.** Бэкенда нет, регистрироваться в Formspree/Tally запрещено брифом. CSP разрешает `form-action 'self' mailto:`.
- **Альтернативы.** Cloudflare Pages Function с записью в KV/D1 — качественнее, но требует настройки аккаунта; вариант описан в вопросах Антону.

## 2026-10-02 · D10 · Локализованная 404 и формат URL

- **Решение.** `trailingSlash: 'always'`, `build.format: 'directory'` (чистые URL `/features/`). Маленькая интеграция в `astro.config.mjs` переносит `/ru/404/index.html` → `/ru/404.html`: Cloudflare Pages отдаёт ближайший вверх по пути `404.html`, поэтому на `/ru/…` промахи будет русская 404. 404 — `noindex`, исключена из sitemap.
- **Альтернативы.** Одна двуязычная 404 (проще, но хуже для RU-аудитории).

## 2026-10-02 · D11 · Самопроверка вместо Lighthouse

- В мокапе и примерах — только сорта и регионы (Красностоп/Кубань, Саперави/Кахетия, Арени/Вайоц-Дзор, Кокур/Крым), **без названий виноделен**, чтобы не рекламировать конкретные вина.
